# 스키마는 추가만 하고, 보고서는 JSON 한 열에 저장한다

보고서는 한 번 만들면 다시 만들지 않는 자산이라서, 스키마를 바꾸다 기존 행을 잃으면 그 비용(파싱 수 분 + LLM 비용)을 다시 치러야 한다. 그래서 SQLite 스키마는 `PRAGMA user_version`으로 버전을 매기고 열·테이블을 추가하는 마이그레이션만 한다. 보고서는 섹션·재현 체크를 테이블로 나누지 않고 Pydantic 구조를 JSON 한 열에 통째로 저장해, 보고서 형식이 바뀌어도 스키마 변경이 필요 없게 한다.

## Considered Options

- 보고서 정규화(섹션·재현 체크 항목별 테이블): 보고서 형식을 바꿀 때마다 마이그레이션이 필요하고, 옛 형식 행을 옮기거나 지워야 하는 상황이 생긴다.
